# AI tools log — where they got it wrong

Tools used: Claude Code (design + implementation), NVIDIA API catalogue models (tagging, judging, ranking — exact models per run are recorded in each `run_meta.json`).

Raw outputs that quote the screenplay live in the Google Drive raw-outputs folder, never in this repo.

| # | Tool | What I asked | What it did wrong | How I caught it | What I changed |
|---|---|---|---|---|---|
| 1 | Claude Code | Scan the 50 screenplays for structure stats | Data-scan regex matched only `Scene end:`; reported 49 episodes because Episode 6 uses `SCENE END:` | Count didn't match the 50 files | Case-insensitive parser, parse-health summary + fail-loud threshold, parser test for the upper-case variant |
| 2 | Claude Code | Design the LLM response cache | First cache key was `model + prompt`, so 3 majority-vote runs would have returned one cached answer three times and faked "agreement" | Design review | Vote index added to the cache key; test `test_cache_hit_and_vote_index_in_key` |
| 3 | Claude Code + NVIDIA catalogue | Pick default models | The planned default model IDs (`nvidia/llama-3.3-nemotron-super-49b-v1`, `meta/llama-3.3-70b-instruct`) no longer exist; two other models are *listed* by `/v1/models` but return 404 when called; a reasoning model returned an empty `content` with all 200 tokens spent on reasoning | Live probe calls before the first run | Fallback chains per stage, 404 → next model, empty content falls back to the reasoning field, larger `max_tokens`, models re-chosen from a live probe |
| 4 | Nemotron-3 Ultra (tagger) | Score each hook/cliff 0–10 | Score inflation: median hook 9, median importance 9, 80–87% of all tags ≥ 8 — the scores barely separate a great moment from an ordinary one, so the ranking was close to noise | First full run (2026-11-07): recall@20 vs the 12-pick gold set was **1/12**, although the candidate pool contained 9/12 gold moments | Baseline recorded; fixes are already in the plan: calibration anchors (Task 13), pairwise ranking (Task 17), and judging every candidate instead of the top 30 |
| 5 | Claude Code (my plan) | Choose which candidates the judge sees | Plan capped the judge at the top 30 by tagger window score; because of #4 that cut was arbitrary — 8 of the 9 gold moments in the pool sat at window score 7.1–7.8, just below the cut (~8.0), and unjudged candidates were then ranked alongside judged ones | Tracing each missed gold pick back to its stage | Judge cap to be raised to cover the pool (95 candidates ≈ +65 cheap calls) |
| 6 | Nemotron-3 Ultra (tagger) | Quote the exact line for each tagged beat | 11 quote mismatches: in E18 it copied the transcript's `DIALOGUE NAME (Emotion):` label instead of the spoken words (8 of 11); elsewhere it merged two consecutive lines into one quote; plus 23 references to beat IDs that don't exist | The quote check (fuzzy match ≥ 0.8) and unknown-ID check rejected them — no invented quote reached the output | Kept the rejection; candidate fix is to strip speaker labels from the quote before matching |
| 7 | Nemotron-3 Ultra (Experiment A, "Plan A") | Read a whole episode and return promo clips with start/end timestamps | Only **6 of 19** clips (32%) were usable: 12 started or ended off a shot boundary, 3 cut through a spoken line, 1 was the wrong length (eps 1, 10, 20, 30, 40) | `check_naive_clip` — the only place LLM-written timestamps are parsed | Architecture: the LLM never writes timestamps; it tags beat IDs and picks between code-built cuts (stages 4, 5, 8) |
| 8 | Nemotron-3 Ultra (Experiment B, hindsight) | Tag the same episodes with and without the full-show context | With context it picked **16 moments it never picked without context**; their clips scored **5.59/10** on the blind stranger test, vs **7.75** for the 4 beats tagged both ways; 3 clips scored ≤ 4 — knowing the ending makes setup moments look like hooks (eps 1, 7, 13, 19, 25, 31, 37, 43) | Blind judge scores of the context-only picks | Judge stays blind (no show context), standalone carries 25% of the final score, prompt tells the tagger to score hooks as a stranger |
| 9 | Claude Code (my experiment code) | Measure how much context raises a beat's score | First version treated "not tagged without context" as a score of 0, so it reported 19 "risen" beats when only 4–5 were true score rises — it conflated *choosing different moments* with *scoring the same moment higher* | Reading the rows before writing them up | `tagged_without` flag, separate `score_rose` / `context_only` counts, test `test_hindsight_separates_context_only_picks` |
| 10 | Claude Code (clip builder) | Build clips that never cut through a spoken line | The builder treated a mid-line cut as a soft score penalty, while the spec and the invariant check treat it as a hard rule; the screenplays also overlap (a line ends 0.1 s after the next shot starts), so snapping to the shot start clipped a line. One E20 promo at rank 17 failed the invariant in the M2 run (pass rate 98.9%); the baseline's 100% was luck | `invariant_pass_rate` in `eval`, then tracing the failing promo's start beat | `snap_start` starts after a bleeding line when the hook stays within 3 s; mid-line cuts are now dropped, never emitted; tests `test_snap_start_avoids_line_bleeding_into_shot`, `test_build_never_emits_mid_line_cut` |
| 11 | Nemotron-3 Ultra (pairwise judge) | "Which of these two would you post first?" | Strong position bias: it picked whichever clip was shown first in **24 of 28** comparisons (86%), so the M3 ordering of finalists was mostly an artefact of presentation order | `pairwise_first_position_rate`, tracked in `run_meta.json` from the start for exactly this reason | Every pair is now asked in both orders; a win counts only when both agree, otherwise it is an Elo draw; `pairwise_consistent_rate` is reported. Rerun with both orders: it agreed with itself on only **6 of 28** pairs (21%), first-shown still won 89% — the stage now does no harm (draws fall back to the judge's scores) but adds little signal with these free models |
